## Dev Notes

### Context from QA Review

This story addresses **Issue #1** from `docs/qa/EPIC-2-RELIABILITY-REVIEW-FINDINGS.md`:
- **Severity:** HIGH - Production Blocker
- **Problem:** Test configuration uses plain HTTP URL but HTTP client enforces SSL/TLS
- **Security Risk:** Live WiFi password and auth token committed to repository
- **Impact:** Connection failure + credential exposure

### Current Configuration (BROKEN)

**File:** `firmware/main/test_config.h`
```c
#define TEST_WIFI_SSID      "Davis"
#define TEST_WIFI_PASSWORD  "jeffmary"              // ← Credential exposure
#define TEST_SERVER_URL     "http://206.189.210.203" // ← HTTP (wrong)
#define TEST_AUTH_TOKEN     "1bc580a0-5be2-4b83-99f6-e8e08a29a334" // ← Credential exposure
#define ENABLE_TEST_MODE    1
```

**File:** `firmware/main/http_client.c:476`
```c
esp_http_client_config_t config = {
    .url = url,  // Contains http:// from test config
    .transport_type = HTTP_TRANSPORT_OVER_SSL,  // ← Forces SSL!
    .crt_bundle_attach = esp_crt_bundle_attach,
};
```

**Result:** SSL client attempting HTTP endpoint = connection failure

### Production Server Details

- **Base URL:** `https://206.189.210.203` (HTTPS required)
- **Status Endpoint:** `POST /api/v1/control/status`
- **Certificate:** ESP32 cert bundle includes root CAs for validation
- **TLS Version:** TLS 1.2+ supported

### Implementation Options

**Option 1 (RECOMMENDED): Remove test_config.h entirely**
- Simplest and most secure
- Use only NVS provisioning for all configurations
- Eliminates credential exposure risk
- Reduces code complexity

**Option 2: Secure test mode with environment variables**
- Keep test mode for development convenience
- Read credentials from compile-time environment variables
- Never commit credentials to repository
- Add CMakeLists.txt checks for required env vars

**Option 3: Fix URL only (minimal change)**
- Change HTTP to HTTPS in test_config.h
- Replace real credentials with dummy values
- Quick fix but still has security concerns

### Security Best Practices

From PRD (docs/prd.md:53-54):
> "All server communication must use HTTPS with certificate validation"

From ESP-IDF Security Best Practices:
- Never commit credentials to version control
- Use secure provisioning methods (NVS, BLE, etc.)
- Validate TLS certificates in production
- Use compile-time or runtime configuration for secrets
