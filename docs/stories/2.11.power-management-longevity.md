# Story 2.11: Power Management & Device Longevity

## Status
**Approved**

---

## Story

**As a** System Operator,
**I want** the ESP32 firmware to use intelligent power management while maintaining WiFi connectivity,
**so that** devices consume 10x less power, generate less heat, have longer lifespan, and provide comprehensive health telemetry for remote monitoring.

---

## Acceptance Criteria

### Power Management (Issue #2)

1. **WiFi Modem Sleep Enabled**
   - WiFi modem sleep configured with `WIFI_PS_MIN_MODEM`
   - WiFi connection remains stable and connected
   - Radio sleeps between beacon intervals automatically
   - Logs confirm modem sleep enabled successfully

2. **Dynamic CPU Frequency Scaling**
   - `CONFIG_PM_ENABLE` enabled in sdkconfig
   - CPU scales between 80MHz (idle) and 240MHz (active)
   - Power management configured with light sleep support
   - Logs confirm frequency scaling active

3. **Power Consumption Reduction**
   - Average current consumption < 50mA (down from ~200mA)
   - WiFi connectivity stable over 1+ hour with PM enabled
   - Status reports continue every 60 seconds
   - Device responds to server commands reliably

### Enhanced Watchdog Coverage (Issue #3)

4. **Idle Task Monitoring**
   - Task Watchdog monitors both CPU core idle tasks
   - `idle_core_mask` configured for cores 0 and 1
   - Boot logs show all monitored tasks
   - Watchdog triggers correctly on idle task starvation test

### Power & Health Telemetry (Issue #4)

5. **Expanded Device Status**
   - Status reports include: free heap, WiFi PS mode, CPU frequency
   - Status reports include: watchdog reset count, last reset reason
   - Backend schema updated with new telemetry fields
   - Database migration applied successfully

6. **Remote Monitoring Capability**
   - Server receives and stores all new telemetry metrics
   - API returns complete device health data
   - Telemetry validates power management is working remotely
   - Historical health data available for trending

## Dev Notes

### Context from QA Review

This story addresses **Issues #2, #3, and #4** from `docs/qa/EPIC-2-RELIABILITY-REVIEW-FINDINGS.md`:

**Issue #2: Power Management Disabled**
- **Severity:** HIGH (conditional blocker for solar/battery)
- **Impact:** 10x higher power consumption than necessary
- **Benefits:** Lower heat, longer lifespan, battery viability

**Issue #3: Incomplete Watchdog Coverage**
- **Severity:** MEDIUM (safety enhancement)
- **Impact:** WiFi stack hangs may go undetected
- **Benefits:** Better failure detection and recovery

**Issue #4: Incomplete Telemetry**
- **Severity:** MEDIUM (operational visibility)
- **Impact:** Cannot validate power optimization remotely
- **Benefits:** Remote monitoring, issue diagnosis, reliability tracking

### Product Owner Decision: Keep WiFi Connected

**Key Insight:** WiFi modem sleep provides power savings WITHOUT disconnecting
- WiFi stays connected at all times (more reliable)
- Radio sleeps between beacon intervals (50% power reduction)
- Transparent to application layer (no code changes needed)
- Better than disconnecting (no reconnection failures)

### Power Management Technical Details

**WiFi Modem Sleep (`WIFI_PS_MIN_MODEM`)**
- Beacon interval: typically 100ms
- Radio on: ~5-10ms per beacon
- Radio off: ~90-95ms per beacon
- Average current: ~100mA → ~50mA (50% reduction)
- Connection: remains stable, no disconnects

**CPU Frequency Scaling**
- Idle: 80MHz (low power, sufficient for monitoring)
- Active: 240MHz (full speed for control decisions)
- Automatic switching based on FreeRTOS task activity
- Additional 30-50% power savings when idle
- No impact on control loop timing

**Light Sleep**
- Entered during `vTaskDelay()` and idle periods
- WiFi connection maintained via DTIM beacon wakeup
- Additional power savings during long delays
- Wakeup latency: <3ms (acceptable for our application)

**Combined Power Savings**
- Baseline: ~200mA continuous (no PM)
- With WiFi PS: ~100mA (50% savings)
- With CPU scaling: ~50-70mA (additional 30-50% savings)
- With light sleep: ~30-50mA during idle (up to 80% savings)
- **Result: 10x power reduction** (200mA → 20-50mA)

### Device Lifespan Benefits

**Thermal Stress Reduction**
- Lower average CPU frequency → less heat generation
- Cooler operation → slower component degradation
- Reduced thermal cycling → longer capacitor life
- Less stress on voltage regulators → increased reliability

**Battery Life Impact**
- 10,000mAh @ 200mA = 50 hours (2.1 days)
- 10,000mAh @ 30mA = 333 hours (13.9 days)
- **6.7x battery life improvement**

### Watchdog Coverage Enhancement

**Current Monitoring:**
- ✅ `control_loop_task` (main application logic)

**New Monitoring:**
- ✅ Core 0 idle task (FreeRTOS scheduler health)
- ✅ Core 1 idle task (FreeRTOS scheduler health)

**Why Monitor Idle Tasks?**
- Idle tasks MUST run for healthy operation
- If idle tasks don't run → scheduler imbalance or CPU hogging
- Early indicator of system degradation
- Standard ESP-IDF best practice

**Risk Scenario Prevented:**
- WiFi stack hangs → control loop still runs → watchdog doesn't trigger
- With idle monitoring → eventual starvation → watchdog triggers → recovery

### Telemetry Fields Specification

**New Firmware Fields:**
```c
typedef struct {
    // Existing
    const char *relay_state;
    uint32_t uptime_seconds;
    int32_t wifi_rssi;
    uint32_t countdown_timer_remaining;
    const char *firmware_version;

    // NEW
    uint32_t free_heap_bytes;          // Memory health indicator
    uint8_t wifi_ps_mode;              // 0=none, 1=min_modem, 2=max_modem
    uint16_t cpu_freq_mhz;             // Current CPU frequency
    uint8_t watchdog_reset_count;      // Cumulative from RTC memory
    const char *last_reset_reason;     // "POWERON", "WATCHDOG", etc.
} device_status_t;
```

**New Backend Columns:**
```python
free_heap_bytes = Column(Integer, nullable=True)
wifi_ps_mode = Column(SmallInteger, nullable=True)
cpu_freq_mhz = Column(SmallInteger, nullable=True)
watchdog_reset_count = Column(SmallInteger, nullable=True)
last_reset_reason = Column(String(20), nullable=True)
```

**All nullable for backward compatibility with existing devices**
