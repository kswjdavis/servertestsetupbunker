# Story 2.1: ESP32 Dead-Man Timer Implementation

## Status

## Story
**As an** ESP32 device,
**I want** a 5-minute countdown timer that resets when server commands arrive,
**so that** fans automatically turn ON if server communication is lost (fail-safe).

## Acceptance Criteria

1. Timer initializes to 300 seconds (5 minutes) on boot
2. Timer decrements every second in FreeRTOS task
3. Timer resets to 300 when server sends reset_countdown=true
4. When timer reaches 0, relay_force_on() is called
5. Timer state is thread-safe (atomic operations or mutex)
6. Timer remaining value is readable by status reporting task
7. Timer expiration logs "Dead-man timer expired - entering fail-safe" (FR17, FR18, FR19)
8. Timer does NOT reset automatically - only on server command
9. Timer continues running even after expiration (for monitoring)
10. Unit tests verify timer behavior

## Dev Notes

### Timer Implementation (FreeRTOS)

```c
// deadman_timer.c (excerpt)
static atomic_uint_least32_t s_countdown_seconds =
    ATOMIC_VAR_INIT(DEADMAN_TIMER_INITIAL_VALUE);
static atomic_bool s_expired = ATOMIC_VAR_INIT(false);

static void deadman_timer_handle_tick(void)
{
    uint32_t snapshot =
        atomic_load_explicit(&s_countdown_seconds, memory_order_acquire);
    if (snapshot == 0U) {
        return;
    }

    snapshot = atomic_fetch_sub_explicit(
        &s_countdown_seconds, 1U, memory_order_acq_rel);

    if (snapshot == 1U) {
        bool already_expired =
            atomic_exchange_explicit(&s_expired, true, memory_order_acq_rel);
        if (!already_expired) {
            ESP_LOGE(TAG, "Dead-man timer expired - entering fail-safe");
            relay_force_on();
        }
    }
}

#if defined(ESP_PLATFORM)
static void deadman_timer_task(void *pvParameters)
{
    (void)pvParameters;
    for (;;) {
        vTaskDelay(pdMS_TO_TICKS(1000U));
        deadman_timer_handle_tick();
    }
}
#endif

void deadman_timer_reset(void)
{
    atomic_store_explicit(
        &s_countdown_seconds, DEADMAN_TIMER_INITIAL_VALUE, memory_order_release);
    atomic_store_explicit(&s_expired, false, memory_order_release);
    ESP_LOGI(TAG, "Dead-man timer reset");
}
```

The module uses C11 atomics for thread-safe access across the FreeRTOS
task, HTTP response handler, and status reporter. When compiled for tests,
the logging macros fall back to `fprintf` and the `deadman_timer_test_tick`
hook enables deterministic ticking without FreeRTOS.

### Integration with Server Response

When server response arrives with `reset_countdown: true`:
```c
void handle_server_response(server_decision_t decision) {
    if (decision.reset_countdown) {
        deadman_timer_reset();
    }

    if (!decision.shutdown_allowed) {
        relay_force_on();
    }
}
```

### 🚨 CRITICAL FINDING: Relay Lock Behavior (Separate from Story 2.1)

**Scope:** This finding relates to **relay controller** (Story 2.2), not dead-man timer (Story 2.1)

**Issue:** After fail-safe triggers, relay remains **permanently locked** until manual reboot, even when:
- Server communication restored (HTTP 200)
- Server sends `reset_countdown=true`
- Server sends `shutdown_allowed=true`

**Observed:**
```

I (64866) deadman_timer: Dead-man timer reset
W (64870) main: Server allowed shutdown but relay locked in fail-safe state
```

**Impact:** 🔴 **CRITICAL** for remote deployment
- Defeats remote management (requires manual site visit for every fail-safe event)
- Over-conservative for IoT devices (appropriate for local devices only)

**Root Cause:** `firmware/main/relay_controller.c:131-142`
- `relay_force_on()` sets `s_locked = true` permanently
- `relay_set_off()` checks lock and refuses to operate
- Lock **never cleared** except on reboot

**Recommendation:** Address in Story 2.2 review or create new story
- Option 1: Add `relay_unlock_on_communication_restored()` function
- Option 2: Time-based auto-unlock after N minutes
- Option 3: Configuration flag for lock behavior (permanent vs recoverable)
